# Передача доступов новой сессии

Не вставляйте токены, пароли и приватные ключи в GitHub или Markdown.

## То же рабочее окружение

Новая сессия может использовать локальный `.env` и `.local_ssh/newtech_vps_ed25519`; оба пути игнорируются Git. Значения нельзя печатать в ответах и нельзя добавлять в commit.

## Другое окружение

1. Клонировать репозиторий.
2. Создать `.env` по `.env.example`.
3. Передать значения через защищенный ввод или секрет-хранилище.
4. Скопировать Google OAuth token/secret в `secrets` вне Git.
5. Передать SSH private key через секрет-хранилище.
6. Проверить `git check-ignore .env .local_ssh`.

Сначала выполнить dry-run, затем боевой запуск.
